# 对接说明（给 QQ 机器人组）

这份文档写给**写 QQ 机器人**的同学：怎么让机器人读写这个知识库、返回的东西长什么样、
哪些字段绝对不能往群里发、以及我们踩过的坑。

面向对象：会写 Python、能跑命令行，但没接触过这个库的人。
数据库本身长什么样（表、字段、视图）在 `schema/schema.sql` 里；
这份只讲**怎么用**。

> 维护：zeplyn（学创部技术组）。接口有变动会同步改这份文档，改动走 PR。

---

## 一、总览：机器人不直接连数据库

```
QQ 群 ── AstrBot ──┬── python -m cli ...        ← 机器人用这个（推荐）
                   └── HTTP 127.0.0.1:8000      ← 也可以，见第七节
                                  │
                           ┌──────┴──────┐
                           │  知识库服务  │
                           └──────┬──────┘
                     ┌────────────┴────────────┐
              MySQL（成员/活动/参与）        向量库（经验正文）
                   两者靠 id 关联：经验的 metadata 里记着 author_id / activity_id
```

**为什么不直接写 SQL**：表字段以后会动，而命令行和 HTTP 这层是稳定的；
而且服务端替你把关（重复登记会挡、类型不对会拒），直接写库没人拦。

---

## 二、最重要的一节：输出约定

命令行和你的代码之间只有一种约定：**stdout 上永远只有一行 JSON，失败时也打**。

```json
{"ok": true,  "code": "ok",       "data": [ ... ], "message": "找到 3 条", "low_confidence": false}
{"ok": false, "code": "no_match", "data": [],      "message": "没找到相关的经验", "low_confidence": true}
```

| 字段 | 用途 |
|---|---|
| `ok` | 这次调用成功没有 |
| `code` | **机器分支看它**，别去 message 里找"错误"两个字 |
| `data` | 真正的内容（数组或对象） |
| `message` | 已经写好的中文，**直接念给用户听** |
| `low_confidence` | 搜索结果"不太确定"时是 `true`，话术要软一点（见第四节） |

加 `--pretty` 会变成缩进形式，人看方便——但还是 JSON，不是表格。

**这样设计的好处**：你不用去啃中文报错，也不用猜"stdout 是 JSON 还是报错堆栈"。
看退出码决定怎么做，看 `code` 决定说什么，`message` 直接念。

### 退出码（机器人的分支依据）

| 退出码 | 含义 | 机器人该做什么 |
|---|---|---|
| **0** | 成功。**包括"一条都没搜到"** | 按 `data` / `code` 正常回话 |
| 1 | 其它（比如服务返回的不是 JSON） | 记日志，回"出错了" |
| 2 | **你自己命令拼错了** | 记日志，别念给用户 |
| 3 | 服务连不上 / 超时 | 回"知识库服务暂时不可用" |
| 4 | 404 找不到 | 回"没有这条记录" |
| **5** | 409 冲突（比如重复登记） | ★ **当作"已经做过了"，算成功**，重试是安全的 |
| 6 | 400 / 422 服务端拒绝 | 把 `message` 念给用户 |
| 7 | 服务在跑、但它说数据库不通 | 回"数据库暂时不可用" |

★ **5 和 0 都是成功。** 重复登记返回 409，对想重试的机器人来说这是好消息，
别当成错误处理——不然用户会看到莫名其妙的"失败"。

## 三、机器人最常用的命令

共同参数：`--base URL`（服务地址，默认 `http://127.0.0.1:8000`）、`--pretty`（好看点）。

```bash
# 自检：服务通不通
python -m cli health

# 语义检索（核心）：问一句话，找最像的经验
python -m cli exp search "设备出故障了咋办" --top-k 5

# 按类型/标签筛选、分页
python -m cli exp list --type 笔记 --tag 设备 --limit 50

# 看某条经验（顺带把人名/活动名翻出来）
python -m cli exp get exp-12

# 录一条经验（--content - 可从标准输入读；带 --author-id 就署名）
python -m cli exp add --content "……" --type 笔记 --tags 场地,设备

# 给还没标签的经验补标签（只补空，不覆盖人工写的；幂等）
python -m cli exp tag --dry-run
python -m cli exp tag

# 删一条经验（⚠ 删了找不回来）
python -m cli exp delete exp-12

# 成员：名单 / 详情 / 个人活动履历
python -m cli member list
python -m cli member get 30
python -m cli member history 30

# 活动系列、活动场次、参与记录
python -m cli series list
python -m cli activity list
python -m cli part list --activity-id 5
python -m cli part add --activity-id 5 --member-id 30 --role 场务

# 报表：工作量 / 谁没干过 / 轮值分布
python -m cli report by-member
python -m cli report never-participated
python -m cli report rotation
```

★ `part add` **没有** `--honor` 参数，这是故意的：写接口不分辨是谁在写，
不能让群里任何人给自己报荣誉（见第九节"还没做的事"）。

## 四、回答"XX 怎么办"的完整流程

```bash
python -m cli exp search "设备出故障了咋办"
```

拿到结果后按**相似度分档**决定话术：

| 情况 | 返回 | 怎么回 |
|---|---|---|
| 最像的一条 ≥ 0.55 | `ok`，`low_confidence: false` | 直接把内容贴出来 |
| 0.45 ~ 0.55 | `ok`，`low_confidence: true` | "我找到一条，可能相关：……" |
| 都不到 0.45 | `no_match`，`data: []` | "库里还没有这方面的经验，要不要记一条？" |

★ **0.45 / 0.55 这两个数字是网页和命令行共用的**，写在 `cli/exp.py` 的
`DEFAULT_MIN_SIMILARITY` / `CONFIDENT_SIMILARITY` 里。要调就两边一起调，
别在机器人里另写一套——不然同一个问题，网页说"找到了"、机器人说"没找到"。

★ **相似度是"像不像"，不是"对不对"。** 它只说明两句话意思接近，
不能说明那条经验适用于当前这个具体情况。所以别说"这就是答案"，
说"库里有一条相关的"更准。

**要补人名/活动名**：`exp search` 的每条结果里 `metadata` 带着
`author_id` / `activity_id` / `participation_id`，拿这些 id 去
`python -m cli member get <id>`、`activity list` 就能翻成人看得懂的名字。
（`exp get` 那一条会自动翻好，检索结果不翻——一页 5 条要查 5 次库，慢。）

## 五、字段：哪些能往外发、哪些绝对不能

**能往外发的**（就是数据库视图 `v_member_public` 里的全部字段）：

```
id  name  gender  grade  major  join_term  status  org_unit  title
skills  bio_short  avatar  honors
```

**绝对不能发到群里的**（这些字段在基表里，不在视图里，读接口也读不到）：

```
student_no  学号      class_no  班级      birthday   生日
phone       手机      qq  wechat  email    联系方式
bio_long    详细介绍   contribution  对部门贡献（评优用）   remark  备注
```

★ 两个要留神的地方：

1. **读不到，但写接口能写。** `POST /api/members` 是接受 `student_no` /
   `phone` / `email` 的。机器人**不要**去写这些字段——那条路是留给管理员补录的。
2. **能读到的也不代表能发。** 比如 `honors`、`bio_short` 是"对外字段"，
   但把它和某场活动的分工凑在一起发到大群，性质就不一样了。发之前想一下：
   这句话我当面跟当事人说，合适吗？

## 六、机器人跑在哪、要不要口令

| 情况 | 要不要口令 |
|---|---|
| 机器人和服务在**同一台机器**上（现在的部署就是这样，走 `127.0.0.1`） | **不用**，读和写都免 |
| 从别的机器调 | **要**：`/api/` 下**所有方法（连 GET 也要）**都要 `KB_SHARED_PASSWORD` |

★ 所以现在**什么都不用配**，默认就打 `127.0.0.1:8000`。要换地址用环境变量
`KB_API_BASE`，或命令行加 `--base`。**别把地址写死在代码里**——服务挪个端口
就要改你的代码，很冤。

★ 口令是**部门共享**的，不区分是谁在写。这也是为什么 `part add` 不开放荣誉字段。

## 七、不想用命令行？直接调 HTTP

服务就是 FastAPI，`http://127.0.0.1:8000/docs` 有能点的接口文档。
下面是全量清单（`/api/` 前缀省略）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 自检：数据库通不通、库里多少条 |
| POST | `/auth/login` · `/auth/logout` · GET `/auth/me` | 口令登录（同机不需要） |
| GET | `/experience` | 列表 + 筛选：`type` `tag` `author_id` `without_tags` `q` `limit` `offset`。注意这里的 `q` 是**字面**包含（找"投影"就只找带"投影"两个字的），语义检索走下面那条。**筛选后的总条数在响应头 `X-Total-Count`** 里 |
| GET | `/experience/search` | **语义检索**（核心）。`q` 必填，`top_k` 默认 5、上限 20 |
| GET | `/experience/keyword` | 关键词字面匹配（只用来和语义检索做对照，别当主路径） |
| GET | `/experience/{exp_id}` | 单条详情（自动把 author_id 翻成人名） |
| POST | `/experience` | 录入经验 |
| PATCH | `/experience/{exp_id}` | **只能改标签**，请求体 `{"tags": [...]}` |
| DELETE | `/experience/{exp_id}` | 删除 |
| GET | `/members` | 成员名单（已脱敏），`keyword` 可筛姓名/组 |
| GET | `/members/{id}` · `/members/{id}/history` | 成员详情 / 个人活动履历 |
| POST | `/members` | 新增成员 |
| GET/POST | `/series` · `/activities` · `/participations` | 系列 / 活动场次 / 参与记录 |
| GET | `/cards/members` · `/cards/activities` | 介绍卡（拼好的卡片文字，直接能发群） |
| GET | `/reports/by-member` · `/never-participated` · `/rotation` | 报表 |
| GET | `/meta` | 各种枚举值（经验类型、角色、状态……），下拉框和校验都用它 |

**检索返回长这样**（这是机器人最常打的一个）：

```json
[
  {
    "exp_id": "exp-12",
    "content": "（经验正文）",
    "similarity": 0.712,
    "metadata": {
      "type": "笔记",
      "tags": ["场地", "设备"],
      "author_id": 30,
      "activity_id": 5,
      "created_at": "2026-10-12T09:00:00",
      "source": "群内整理"
    }
  }
]
```

## 八、踩过的坑

1. **标签里不能有逗号。** 标签存进向量库时是拼成逗号串的（`a,b,c`），读回来按逗号拆。
   所以标签里一旦有逗号，**一个标签会静默变成两个**——不报错、也查不出是哪来的。
   服务端已经在入口拦了（返回 400），你写的时候别自己拼。

2. **`tags` 读出来是数组。** 别自己按逗号 split 一遍，读到的已经是拆好的。

3. **别用"删了重加"来改经验。** 那会换一个新的 `exp_id`，别人参与记录里
   关联的 `exp_ids` 就断了，而且不报错。改标签用 PATCH / `exp tag`；
   正文要改，宁可新加一条。

4. **一个活动里，一个人只能登记一条参与记录**，重复登记返回 409（见第二节：
   这是"已经做过了"的意思）。同一个人在同一场活动里有多个角色（比如又做场务
   又做主持），写成一个角色字符串（`场务、主持`），不要写两条。

5. **`honors` / `skills` / `exp_ids` 是 JSON 字段**（数据库上有 `json_valid` 约束）。
   给数组就给真的数组 `["救急英雄"]`，别给字符串 `"救急英雄"`，否则会被数据库拒掉。

6. **相似度不是判断对错的标准。** 见第四节。

7. **删除是真删。** 经验的删除是**硬删除**（向量库里直接删掉，找不回来）；
   而**目前还没有删成员的接口**（成员表上那个软删除字段 `deleted_at` 只有库里有）。
   机器人手上别攥着"删"这种危险操作。

8. **机器人自己对输入设个上限。** 群里有人粘一段几千字的聊天记录进来，
   会把检索结果冲淡。建议 `exp add` 之前自己截断或拒绝。

9. **`exp search` 默认只回 5 条、上限 20。** 想要更多得显式给 `--top-k`，
   但给太多没有意义——第 10 条往后基本都不相关了。

## 九、还没做的、以及要留神的事

- **没有按人鉴权**。写接口认的是"口令对不对"，不认"是谁"。所以：
  机器人**不应该**开放"让群里任何人给自己登记分工/荣誉"这种命令。
  真要开放，得先定一份白名单（谁在群里说话可以触发写操作），
  这个名单归部里定，不是技术能替你决定的。
- **没有 HTTPS**。口令在校内网里是明文传的，抓包能拿到。别在群里贴口令。
- **读接口现在是公开的**（校园网内谁都能看介绍卡、搜经验）。这是有意选的方案，
  但你往群里发东西时心里要有数：库里的内容本来就半公开。
