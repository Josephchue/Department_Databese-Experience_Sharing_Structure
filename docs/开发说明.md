## 这个库能干什么

三件事。

### 1. 可检索的经验知识库

把办活动踩过的坑写成一条条文字存起来，然后**用大白话就能搜到**。

普通搜索是比对文字：库里写的是「投影仪不亮」，你搜「设备出故障了咋办」——
一个字都对不上，一条也搜不出来。这个库做的是**按意思搜**，两句话字面上毫无关系，
也能把那条揪出来：

| 你在群里问 | 它能给你捞出来 |
|---|---|
| 「报名的人太少咋办」 | 「可以在班群和部门群二次宣传，或者合并到下一场」 |
| 「设备坏了」 | 「投影仪不亮，先检查 HDMI 线是否松动，备一台笔记本」 |

存储：向量库（Chroma）。非结构化，靠语义相似度召回。

### 2. 活动分工统计

每办一场活动，记一条「**谁** × **哪场活动** × **什么分工**」。记下来之后两个方向都能查：

- **看一场活动**：这场沙龙谁是主讲、谁是执行、谁负责搬设备。
- **看一个人**：某同学这学期参加了哪几场活动，各是什么角色，投入多少小时。

再往上出统计：每个人参与几次、谁**一次都没参与过**（排轮值最该先看这个）、
按学期看活是不是压在少数人身上。

存储：MySQL。结构化，可统计、可出报表。

用途：**换届交接、轮值安排、评优**的依据。

> ⚠️ 这个库**不出五育时长和志愿时长**。需求文档写明了时长不由本系统产出，
> 只统计「谁干了几次、干了什么角色」，是安排工作的参考，不是发放时长的依据。

### 3. 给 QQ 机器人读写

QQBot 组的机器人（AstrBot）能直接读写这个库，群里的样子大概是：

```
同学：@机器人 投影仪不亮咋办
机器人：经验库里有一条相关的 ——
       活动现场投影仪突然不亮，先检查 HDMI 线是否松动，
       备一台笔记本，联系场地管理员拿备用投影。
```

机器人能干四件事：**查经验、写经验、查分工统计、写分工登记**。
入口是我们提供的 [命令行工具（CLI）](#命令行工具cli)——机器人不直接连数据库，
见那一节说明。

一期只在学创部内部跑通，稳定后再考虑开放给全团学联。

## 数据库 Schema 的来源

`schema/schema.sql` **不是我们写的**——它是关系模式的唯一来源，由部长维护。

我们**只读，不手改**：`scripts/init_db.py` 直接执行这份 DDL 建库建表。
表结构确实要动，就在本仓库开分支改，PR 里写清理由，由 owner 审核。

**当前与 `bb38a50` 一致**（该提交同时是 `main` 的 HEAD）。

> 表名为什么叫 `member_position`：`position` 是 MySQL 保留字
> （`POSITION(x IN y)` 函数），裸写 `CREATE TABLE position` 会报
> `ER_PARSE_ERROR`（errno 1064）。owner 在 `bb38a50` 里把表改名，
> 并给全部标识符统一加了反引号。

| 项 | 要求 | 检查命令 |
|---|---|---|
| Python | ≥ 3.11 | `python -V` |
| MySQL | ≥ 8.0 | `mysql --version` |

### 装 MySQL

官网 https://dev.mysql.com/downloads/installer/ 下完整的 MSI（约 400MB，**不要**下 web 版）。

向导里这几屏注意：

1. Setup Type 选 **Server only**（别选 Developer Default，会装一堆用不上的东西）
2. Port 保持 **3306**
3. **设置 root 密码，自己记住**
   - ⚠️ 密码里**不要用 `#`**，`.env` 会把 `#` 之后的内容当注释吃掉
4. Windows Service 那一屏**两个勾都打上**（开机自启）
5. 想直接看表，装个 **MySQL Workbench**（和 Server 一起勾上就行）

### 起项目

```bash
git clone <这个仓库>
cd 知识库

python -m venv .venv
source .venv/Scripts/activate        # Windows Git Bash
# .venv\Scripts\activate             # Windows CMD / PowerShell
# source .venv/bin/activate          # Linux / macOS

pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r requirements.txt

cp .env.example .env                 # 然后编辑 .env，填上你的 MySQL root 密码

python -m scripts.init_db            # 建库 + 建表（应建出 7 张表 2 个视图）
python -m scripts.seed               # 造演示数据（首次会下载向量模型，约 100MB）

python -m uvicorn api.main:app --reload --port 8000
```

打开 http://localhost:8000 就是网页界面，五个页签：语义检索、经验录入、活动分工、介绍卡、报表统计。
**日常用这个页面就够了，不用敲命令**——录经验、改标签、加成员/活动、看介绍卡和报表都在里面。

> 单文件、原生 JS、不需要任何构建工具（见 `web/index.html` 开头）。
> 页面上**刻意没有**学号/手机/邮箱/班级/生日的输入框：写接口目前没有鉴权，
> 谁打开页面都能提交，而这些字段不该经无鉴权的表单流转。
> 要补录这类信息，走数据库或带权限的接口。

> **每个人用的是自己电脑上的 MySQL**，数据库不共享、密码也不共享。
> 共享的是 `schema/schema.sql`——关系模式的唯一来源，谁都不手改。

> ⚠️ **首次下模型如果卡住不动**（注意：不是报错，是进度条不动），
> 是 HuggingFace 的 **xet 传输协议**在国内不通，不是网络断了。
> `api/config.py` 已经设了两个环境变量解决它：
> `HF_ENDPOINT=https://hf-mirror.com`（走国内镜像）+ `HF_HUB_DISABLE_XET=1`（关掉 xet）。
>
> **两个都得设，而且必须在 `huggingface_hub` 被导入之前设好**——
> 它在导入那一刻就把这两个值读成模块常量了，之后再设没有任何作用。
> 所以别在命令行临时 `export` 了事，要设在 `api/config.py` 这种一定会先被导入的地方。

### 输出

默认在 stdout 打**一行 JSON**，失败时也打，机器人不用去解析中文报错：

```json
{"ok": true, "code": "ok", "data": [...], "message": "...", "low_confidence": false}
```

加 `--pretty` 变成缩进版，给人看。

### 退出码

| 码 | 含义 | 机器人该怎么做 |
|---|---|---|
| 0 | 成功，**包括零结果** | 有结果就发；没结果就说「没找到相关经验」 |
| 2 | 参数写错了 | 是机器人自己的 bug，记日志 |
| 3 | 服务连不上 / 超时 | 「知识库服务暂时不可用」 |
| 4 | 404 找不到 | 「没有这条记录」 |
| 5 | 409 冲突 | **当作已经做过了**，算成功（重试安全） |
| 6 | 400 / 422 服务端拒绝 | 把 `message` 给用户看 |
| 7 | 服务在，但数据库不通 | 「数据库暂时不可用」 |
| 1 | 其它 | 通用报错 |

### 为什么机器人走 CLI 而不直连数据库

Chroma 1.5.9 的 `PersistentClient` 文档里写明了它「只适合本地开发和测试」，
两个进程同时开 `data/chroma/`，读的一方**不保证**能看到另一方写的数据。
服务是常驻的、CLI 是短命的——短命进程会读到旧索引，算出已经占用的 id，
然后**静默覆盖**一条经验。不报错，数据就没了。

所以规矩是：**同一时刻只许一个进程碰向量库**，服务当那个唯一进程，CLI 走 HTTP 找它。

附带的好处是校验逻辑零重复：409 重复登记、400 外键不存在、404，
服务端写好一次，CLI 全部继承。机器人写进去的数据和网页录入的走**同一套规则**。

### 两条刻意的限制

- **`part add` 没有 `--honor` 参数。** `/api/reports/by-member` 的荣誉次数是评优依据，
  而写接口没有鉴权。开放给群里的话，任何人都能给自己报一条荣誉，
  事后还看不出是谁报的。CLI 干脆不暴露这个参数。
- **`exp search` 默认按相似度过滤。** 服务端的检索**没有相似度下限**，
  库里只要有数据，问什么都返回 top_k 条。网页那边看得到相似度数字，人自己会判断；
  但机器人不能把凑数的结果当答案发出去。

  实测（种子数据，24 个问句）：相关问句 0.4920–0.7426，不相干问句 0.2598–0.5373。
  **两段是重叠的**，没有哪个数字能把两者切开——不相干里最高的 0.5373
  比相关里最低的 0.4920 还高。所以分两档：

  | 档 | 条件 | 行为 |
  |---|---|---|
  | ① | 低于 `--min-similarity`（默认 **0.45**） | 不返回任何结果，`code: "no_match"`，**退出码仍是 0** |
  | ② | 过了 ①，但最像的不到 **0.55** | 照常返回，但 `low_confidence: true`，机器人该把话说软 |

  第 ② 档是关键：那两条漏网的不相干问句（0.53 上下）会落进这一档，
  机器人说「可能相关」而不是「就是这条」。宁可放过、不可错杀——
  库里有答案却告诉用户「没找到」，比给一条用户自己看得出不太准的更糟。
  详细数字和理由写在 `cli/exp.py` 开头。

### 打标（K8）的三条规矩

`cli exp tag` 只做一件事：给**还没标签**的经验补标签。三条规矩都是有意的：

- **只补空，绝不覆盖。** 人工写过的标签是人的判断，机器不该改。
  实现上保了两层：循环里见到已有标签就跳过；`tagging/rules.py` 的 `tag()`
  按设计只返回「该打什么」，架构上根本没有「覆盖」这个动作。
  这条能成立的前提是幂等——第二遍跑必须一个写请求都不发（有测试钉住）。
- **标签是闭集。** `tagging/keywords.py` 那张表以后靠部员维护；
  语料里冒出一个表里没有的标签，规则版永远打不出来，按它筛就会**静默地漏**。
  所以有一条守门测试：语料里在用的标签必须都在词表里，红了就是该加表了。
- **`--tagger llm` 明确报「未实现」，退出码 2，不偷偷回退到规则版。**
  一期没有能跑大模型的机器（服务在 M710q 上，纯 CPU），而且批量打标要的是
  「同一条经验每次跑出来一样」，大模型做不到。静默回退最坏的地方是：
  机器人以为用的是大模型，实际拿到的是规则版结果。

> 校准数字（实测，种子 8 条）：人工标签 17/17 个、8/8 条都能被规则版打出来；
> 规则版还会**多打** 4 个。注意这是**在训练集上量的**（词表就是照这 8 条写的），
> 不等于准确率——换了真实语料要重新量，不是重新套。

## 接口

| 方法 | 路径 | 说明 |
|---|---|---|

## 数据库结构

7 张表 + 2 个视图。核心关系：

```
activity_series  1 ──N  activity  N ──N  member      （经 participation）
member           1 ──N  member_position
member           1 ──1  account / privacy_consent
```

| 表 | 作用 |
|---|---|
| `member` | 成员档案（内外分层，敏感字段有标注） |
| `activity_series` | 活动系列（品牌/栏目，如「惟学沙龙」） |
| `activity` | 活动场次（系列下具体一次） |
| `participation` | 参与记录：谁 × 哪个活动 × 什么分工 |
| `member_position` | 职务/任期（支持多职务、换届）。⚠️ **表名是 `member_position` 不是 `position`**——后者是 MySQL 关键字 |
| `privacy_consent` | 隐私授权记录 |
| `account` | 账号（学校统一身份 CAS 绑定） |

| 视图 | 作用 |
|---|---|
| `v_member_public` | 对外简版成员卡，**自动脱敏**（不含学号/手机/邮箱/班级/生日） |
| `v_member_history` | 成员活动履历，自动 JOIN 聚合，不用手填 |

### 双库怎么关联

经验本体存在**向量库**里，MySQL 里**没有 experience 表**。两边靠 id 关联：

- `participation.exp_ids`（JSON 列）存 `exp-xxx`，正向指向经验；
- 经验的 metadata 里记 `author_id` / `activity_id` / `participation_id`，反向指回 MySQL。

这几个 id 和 MySQL 的 `member.id` / `activity.id` / `participation.id` 是**同一套**。

### 三个设计要点

- **`participation` 的唯一键是 `(activity_id, member_id, role)`**，不是 `(活动, 人)`。
  这意味着**一个人在一个活动里可以有多个角色**（既当主讲又当执行）。
- **`v_member_public` 视图就是脱敏规则的唯一事实来源**。
  写查询时直接 `SELECT * FROM v_member_public`，不要在代码里再抄一份字段清单——
  抄了就会有两处规则要维护，视图改了代码没改就报 `Unknown column`。
- **向量距离空间必须是 cosine**。Chroma 不指定时用 L2 且返回**平方**距离，
  按「1 − 距离」算出来的不是相似度（真值 0.565 会被算成 0.130），
  而且**不报错**，静默给错数字。详见 `api/vectors.py` 开头那三个坑。
